Spec: tmdb-lookup-tool

Atualizado em 2026-09-05

Resumo

Uma tool no domínio movies consulta o catálogo já existente: searchMovies + getMovieDetails no primeiro hit. Sucesso devolve MovieCatalogDetails completo. Search vazia, query vazia ou TMDB fora devolvem { found: false } — a tool não derruba o turno da IA.

Requirements (cenários BDD)

REQ-1: Lookup com match

  • Dado que searchMovies devolve ao menos um hit
  • Quando a tool é invocada com query (e year opcional como primary_release_year)
  • Então chama getMovieDetails com o id do primeiro hit e devolve { found: true, details }

REQ-2: Search sem resultados

  • Dado que a search devolve results vazio
  • Quando a tool é invocada
  • Então não chama getMovieDetails e devolve { found: false, message }

REQ-3: TMDB fora não quebra o turno

  • Dado que a porta lança TmdbHttpException (timeout, 502, etc.)
  • Quando a tool é invocada
  • Então devolve { found: false, message } e não relança — o agente responde com o que já sabe

Edge cases
  • year ausente: search só com query.
  • year presente: o texto da search continua só o título; a TMDB recebe primary_release_year.
  • imdbId null: ainda é sucesso.
  • query vazia: found: false, sem chamar a porta.
  • Logar a exception e ainda assim devolver found: false.
  • Wiring no agente: fora desta feature; found: false é o que permite o agente continuar.

Contratos

Input { query: string; year?: number }. Sucesso { found: true; details: MovieCatalogDetails }. Sem match ou TMDB fora: { found: false; message: string } (a tool não lança). Porta IMovieCatalogProvider. Código em domains/movies/infrastructure/.
