F1.C1 Redis cota F1.C1 · RedisGuestQuotaRepository

Persistência da cota anônima no Redis, sem HTTP.

Como funciona

getString + parse; increment é read-modify-write e renova TTL 86400.

const currentUsedCount = await this.getUsedCount(guestId);
const nextUsedCount = currentUsedCount + 1;

await this.redis.setWithExpiration(
  this.key(guestId),
  String(nextUsedCount),
  GuestQuotaConstants.TTL_SECONDS,
);

Dados fluindo

guest:quota:<uuid> ausente → getUsedCount = 0 increment → 1, TTL 1 dia increment de novo → 2

Conecta

  • Porta IGuestQuotaRepository
  • GuestQuotaConstants (limit 2, cookie guest-id ainda não usado no HTTP)
  • Próximo: GuestQuotaService (F1.C2)

F1.C2 Serviço F1.C2 · GuestQuotaService

Regra de cota: remaining, recusa no limite sem incrementar, increment só após sucesso.

Como funciona

Lê usedCount no repositório. Se used >= 2, lança 401. incrementAfterSuccess persiste e devolve remaining.

const isQuotaExceeded =
  usedCount >= GuestQuotaConstants.RECOMMENDATION_LIMIT;
if (!isQuotaExceeded) return;
throw new GuestQuotaExceededException();

Dados fluindo

used 0 → remaining 2, assert ok used 1 → remaining 1, assert ok used 2 → 401, increment não é chamado increment 0→1 → remaining 1

Conecta

  • Usa IGuestQuotaRepository (F1.C1)
  • C3 chama assertCanAcceptAnonymousRecommendation
  • C4 chama incrementAfterSuccess no 200

F1.C3 Hook F1.C3 · MovieRecommendationAuthHook

Separa Bearer válido (ilimitado) de visitante (cota). Ainda sem cookie/header HTTP.

Como funciona

Token após Bearer vai para verify; falha vira 401 sem cota. Sem token: cookie guest-id ou UUID, depois assertCanAcceptAnonymousRecommendation.

if (bearerToken) {
  await MovieRecommendationAuthHook.markAuthenticated(
    request, deps.accessTokenProvider, bearerToken,
  );
  return;
}
await MovieRecommendationAuthHook.markAnonymous(
  request, deps.guestQuotaService,
);

Dados fluindo

Authorization Bearer válido → movieAuth.authenticated, sem Redis Bearer inválido → 401 InvalidAccessTokenException sem Bearer + cookie → assert(guestId do cookie) sem cookie → UUID novo no movieAuth.anonymous

Conecta

  • IAccessTokenProvider.verify (módulo auth)
  • GuestQuotaService (F1.C2)
  • C4 registra o preHandler e faz Set-Cookie

F1.C4 HTTP wire F1.C4 · routes + controller

Liga o hook no POST, incrementa cota só no 200 anônimo, cookie e header, CORS expose.

Como funciona

Mesma instância de GuestQuotaService no preHandler e no controller. GET queries sem hook.

if (!isAnonymous) {
  return reply.status(200).send(responseBody);
}
const remaining = await guestQuotaService.incrementAfterSuccess(
  movieAuth.guestId,
);
reply.setCookie(GuestQuotaConstants.COOKIE_NAME, movieAuth.guestId, ...);
reply.header(GuestQuotaConstants.RESPONSE_HEADER_REMAINING, String(remaining));

Dados fluindo

anônimo 200 → Redis +1, Set-Cookie guest-id, X-Guest-Remaining logado 200 → só body LLM falhou → sem increment GET /movie/queries → sem cota

Conecta

  • Hook F1.C3 + serviço F1.C2
  • app.ts exposedHeaders
