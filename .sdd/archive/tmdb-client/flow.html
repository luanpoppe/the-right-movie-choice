Dados fluindo

NODE_ENV=test, sem token → parse ok NODE_ENV=dev, TMDB_ACCESS_TOKEN vazio → boot falha NODE_ENV=prod, token presente → env.TMDB_ACCESS_TOKEN disponível

Exception F1.C2 · TmdbHttpException

Erro de domínio único para falhas HTTP da TMDB, com status HTTP nosso por instância. Constantes do transporte no mesmo módulo.

Como funciona

O handler do Fastify já mapeia qualquer BaseException para error.statusCode. Uma classe só; o adapter escolhe 404, 502, 503, 504 ou 500.

export class TmdbHttpException extends BaseException {
  statusCode: number;

  constructor(message: string, statusCode: number) {
    super(message);
    this.statusCode = statusCode;
  }
}
export class TmdbHttpConstants {
  static readonly TIMEOUT_MS = 5_000;
  static readonly MAX_RETRIES = 2;
  static readonly BACKOFF_BASE_MS = 1_000;
  static readonly API_BASE_URL = "https://api.themoviedb.org/3";
  static readonly DEFAULT_LANGUAGE = "pt-BR";
}

Dados fluindo

TMDB 401 → new TmdbHttpException(..., 502) timeout esgotado → status 504 retry 429 ×2 + falha → status 503

Conecta

  • Usado pelo adapter de filmes (próximo chunk).
  • app.ts já serializa BaseException.

Client HTTP F1.C4 · TmdbHttpClient

async searchMovies(query: string, page?: number): Promise<unknown> {
  const pageNumber = page ?? 1;
  searchParams.set("language", TmdbHttpConstants.DEFAULT_LANGUAGE);
  return this.getJson("/search/movie", searchParams);
}
const maxAttempts = TmdbHttpConstants.MAX_RETRIES + 1;
const isRetryableStatus = status === 429 || status >= 500;
export class MakeTmdbHttpClientFactory {
  static create(params?: Params) {
    const client = new TmdbHttpClient(params);
    return client;
  }

Zod details F2.C3 · TmdbMovieDetailsResponseSchema

Valida o JSON de GET /movie/{id} com append de credits, watch/providers e external_ids — ainda sem mapper nem HTTP.

Como funciona

Campos que a TMDB omite são optional. A chave watch/providers fica entre aspas. Objetos Zod 4 ignoram chaves extras.

export const TmdbMovieDetailsResponseSchema = z.object({
  id: z.number(),
  title: z.string(),
  overview: z.string(),
  poster_path: z.string().nullable().optional(),
  release_date: z.string(),
  runtime: z.number().nullable().optional(),
  vote_average: z.number().optional(),
  genres: z.array(TmdbGenreSchema).optional(),
  origin_country: z.array(z.string()).optional(),
  credits: TmdbCreditsSchema.optional(),
  "watch/providers": TmdbWatchProvidersSchema.optional(),
  external_ids: TmdbExternalIdsSchema.optional(),
});

Dados fluindo

JSON TMDB details+append → safeParse (ainda não no client) sucesso → TmdbMovieDetailsResponse falha → 502 no chunk do adapter

Conecta

  • Entrada do mapper de details (próximo chunk).
  • Não ligado ao TmdbHttpClient neste chunk.

Mapper F2.C4 · TmdbCatalogMapper

Converte JSON já validado (Zod) em DTOs camelCase da aplicação. Sem parse e sem HTTP.

Como funciona

Ano = 4 dígitos no início de release_date. Direção = crew com job Director. Elenco = 5 primeiros. Providers só da fatia BR.

static toCatalogDetails(details: TmdbMovieDetailsResponse): MovieCatalogDetails {
  const searchHit = TmdbCatalogMapper.toSearchHit({ … poster_path: details.poster_path ?? null … });
  const directors = TmdbCatalogMapper.mapDirectorNames(details.credits?.crew);
  const cast = TmdbCatalogMapper.mapCastNames(details.credits?.cast);
  const watchProviders = TmdbCatalogMapper.mapBrazilWatchProviders(details["watch/providers"]);
  const imdbId = TmdbCatalogMapper.mapImdbId(details.external_ids?.imdb_id);
  return { …searchHit, runtimeMinutes: details.runtime ?? null, … };
}

Dados fluindo

TmdbSearchResponse → MovieSearchPage TmdbMovieDetailsResponse → MovieCatalogDetails Zod fail ainda não acontece aqui

Conecta

  • Consome os schemas de search e details.
  • O próximo chunk liga o client: safeParse + este mapper + 502.

Porta+adapter F2.C5 · IMovieCatalogProvider / TmdbHttpClient

Search e details passam a devolver DTOs da aplicação. JSON inesperado vira 502, como JSON inválido.

Como funciona

getJson continua unknown. Depois do 200, safeParse + mapper. Log de warn sem body nem token.

async searchMovies(query: string, page?: number): Promise<MovieSearchPage> {
  const json = await this.getJson("/search/movie", searchParams);
  return this.mapSearchPage(json);
}
private mapSearchPage(json: unknown): MovieSearchPage {
  const parsed = TmdbSearchResponseSchema.safeParse(json);
  if (!parsed.success) {
    Logger.warn("TMDB returned an unexpected payload", { path: "search" });
    throw new TmdbHttpException("TMDB returned an unexpected payload", 502);
  }
  return TmdbCatalogMapper.toSearchPage(parsed.data);
}

Dados fluindo

200 JSON → Zod → MovieSearchPage / MovieCatalogDetails Zod fail → TmdbHttpException 502 404/timeout/retry inalterados

Conecta

  • Implementa a porta tipada.
  • Cache Redis (próximo) ainda não envolve o client.

Loopback F2.C7 · TmdbLoopbackGuard

preHandler Fastify: só a própria máquina acessa as rotas debug. Sem JWT. Sem mudar listen().

Como funciona

IP de request.ip (fallback socket). Normaliza IPv4-mapped. Fora de 127.0.0.1 / ::1 / localhost → 403. Não lê X-Forwarded-For.

if (TmdbLoopbackGuard.isLoopbackAddress(ip)) return;
throw new TmdbLoopbackForbiddenException();

Dados fluindo

127.0.0.1 / ::1 / localhost / ::ffff:127.0.0.1 → passa 192.168.* / IP público / IP vazio → 403

Conecta

  • As rotas debug (próximo chunk) registram este preHandler.

Rotas debug F2.C8 · /debug/tmdb

GETs locais de search e details. Loopback no plugin. Cache só no details. Fora de prod.

Como funciona

Search exige query. Details: cache hit devolve DTO; miss chama o client e grava TTL 24h sem refresh no hit.

app.addHook("preHandler", TmdbLoopbackGuard.createPreHandler());
app.get("/debug/tmdb/search", …);
app.get("/debug/tmdb/movies/:id", …);

Dados fluindo

dev/test → plugin registrado prod → rotas inexistentes query vazia / id inválido → 400 IP não loopback → 403

Conecta

  • Client, cache e guard dos chunks anteriores.
