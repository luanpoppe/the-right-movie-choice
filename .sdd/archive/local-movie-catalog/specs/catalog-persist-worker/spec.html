Spec: catalog-persist-worker

Atualizado em 2026-09-05

Resumo

Worker BullMQ no mesmo processo Fastify consome catalog-movie-persist e chama upsert. Não enfileira (próxima feature). Job = idioma + MovieCatalogDetails.

Requirements

REQ-1: Job válido persiste a ficha

  • Dado que job 157336:pt-BR com details de Interestelar
  • Quando o Worker processa
  • Então chama upsert com esses details e pt-BR
  • E o job termina completed
  • E não chama TMDB

REQ-2: Conflito de IMDb não entra em retry

  • Dado que upsert lança MovieCatalogImdbConflictException
  • Quando o processor trata o erro
  • Então loga o conflito
  • E não reagenda
  • E o job não fica failed por esse conflito

REQ-3: Falha transitória de Postgres tenta de novo

  • Dado que upsert lança timeout/conexão
  • Quando falha a 1ª tentativa
  • Então até 4 corridas (1 imediata + 3 esperas 15 s, 1 min, 5 min)
  • E após a 4ª vai para o set failed (não some do Redis)
  • E cada falha é logada

REQ-4: Mesmo filme não duplica job ativo

  • Dado que já existe job 157336:pt-BR ativo ou waiting
  • Quando um segundo add usa o mesmo jobId
  • Então não há dois processors em paralelo para o mesmo par

REQ-5: Boot liga o Worker sem derrubar o HTTP

  • Entrada Fastify sobe com Redis ok
  • Saída Worker ouvindo; concorrência 3
  • Erro Redis fora no boot → log; HTTP sobe; jobs não processam

REQ-6: Payload inválido não retry infinito

  • Entrada job sem tmdbId ou sem language
  • Saída log; sem backoff 15 s / 1 min / 5 min

REQ-7: Failed fica no Redis para retry manual

  • Entrada 4ª falha transitória (timeout Postgres)
  • Saída job no set failed; removeOnFail guarda os últimos 500
  • E Job.retry() reprocessa
  • Erro conflito IMDb não entra em failed

Edge cases
  • Mesmo event loop: upsert I/O não segura o HTTP.
  • Erro não capturado no processor pode derrubar o processo.
  • Sem enqueue nesta feature: teste via add direto ou processor.

Contratos expostos

Fila: movie-catalog-persist.constants.ts (QUEUE_NAME, jobId).

Payload: movie-catalog-persist-job.entity.ts (MovieCatalogPersistJobData).

Porta: IMovieCatalogRepository.upsert. Conflito: MovieCatalogImdbConflictException.

Failed: REMOVE_ON_FAIL_COUNT; set failed; retry via Job.retry().
