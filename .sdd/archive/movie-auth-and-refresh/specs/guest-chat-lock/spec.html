Spec: guest-chat-lock

Atualizado em 2026-08-30

Resumo

Visitante vê o chat. Após 2 POSTs 200 anônimos (X-Guest-Remaining = 0) ou 401 sem login, o input trava na Welcome e no Chat; banner com /register e /login. Logado nunca trava. Sem toast genérico nesse 401. F5 destrava até a API falar de novo; reset não destrava.

Requirements (cenários BDD)

REQ-1: Trava pelo header após o 2º 200

  • Dado que não há authToken e o POST retorna 200 com X-Guest-Remaining: 0
  • Quando a UI processa a resposta
  • Então input disabled + banner (CTA /register e link /login)

REQ-2: Trava no 401 anônimo

  • Dado que não há token e o POST devolve 401 de cota
  • Quando o erro sobe para a Home
  • Então trava igual ao REQ-1, sem toast genérico

REQ-3: Logado não trava

  • Dado que existe access no AuthContext
  • Quando envia mensagens
  • Então o input permanece habilitado

REQ-4: Reset vs F5

  • Dado que já está travado
  • Quando reset (novo chatId)
  • Então Welcome também permanece travada
  • Quando F5
  • Então o lock some até o próximo remaining 0 ou 401 anônimo

Edge cases
  • Header ausente no 200 → não trava só por isso.
  • Reset não zera o flag de lock da sessão React.
  • Login remove o lock mesmo com flag local true.
  • 401 com token segue o silent-refresh, não este banner.
  • GET /movie/queries não trava.

Contratos

Header X-Guest-Remaining (Axios em minúsculas). Service/Home precisam do remaining. ChatForm e welcome/Form recebem lock. Rotas /register e /login. Sem persistir lock em storage.
