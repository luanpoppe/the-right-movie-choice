Spec: silent-refresh

Atualizado em 2026-08-30

Resumo

O client HTTP das rotas de filme anexa o Bearer do sessionStorage, envia cookies e, se o access expirou (401 com token salvo), chama POST /auth/refresh uma vez, grava o novo access e retenta o POST original. Anônimo não dispara refresh.

Requirements (cenários BDD)

REQ-1: Bearer no POST de recommendation

  • Dado que existe authToken em sessionStorage
  • Quando o SPA chama POST /movie/recommendation
  • Então o client de movies envia Authorization: Bearer e withCredentials: true

REQ-2: Access expirado renova e retenta

  • Dado que o usuário está logado e o access expirou
  • Quando o POST de filme devolve 401
  • Então chama AuthService.refresh(), salva o access no sessionStorage e retenta o POST uma vez

REQ-3: Anônimo não refresha

  • Dado que não há authToken
  • Quando o POST devolve 401
  • Então não chama /auth/refresh

REQ-4: Refresh falhou

  • Dado que o refresh retorna erro
  • Quando o interceptor trata a falha
  • Então limpa o access, tenta logout e navega para /login via react-router

Edge cases
  • Vários 401 → um único refresh (single-flight).
  • Segunda 401 na retentativa → sem loop; fluxo de refresh falhou.
  • Interceptor só no client de movies; authClient sem o mesmo interceptor.
  • GET /movie/queries pode ficar sem Bearer.

Contratos

MovieRecommendationService usa axios de movies com credentials e Bearer opcional. Refresh via AuthService.refresh. Token só no sessionStorage. Navegação via ponte no AuthContext.
