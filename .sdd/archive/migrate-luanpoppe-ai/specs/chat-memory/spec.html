Spec: Memória de chat via @luanpoppe/ai

Atualizado em 2026-09-04

Resumo

Recommendation persiste via checkpointer Redis da lib (memory + threadId = chatId). Sem dual-write no JSON antigo. Query examples sem memory.

Requirements (cenários BDD)

REQ-1: Factory liga memory no mesmo AI

  • Então memory: { type: "redis", url: REDIS_URL, options: { defaultTTL: 1200, refreshOnRead: true } } no mesmo new AI() do provider; pacote @langchain/langgraph-checkpoint-redis; some Redis JSON desta factory

REQ-2: threadId sem reenviar histórico

  • Então threadId = chatId; messages só o turno atual; a lib exige threadId quando há memory

REQ-3: Use case e portas

  • Então execute não chama getHistory; provider troca chatHistory por chatId; porta de histórico só getHistory; HTTP igual

REQ-4: Adapter da porta

  • Então classe nova mapeia ai.memory.getHistory → ChatHistoryEntity; a porta não tem addMessage

Edge cases
  • JSON antigo expira sozinho. Sem prefixo na API da lib. TTL via defaultTTL. Redis 8+/RedisJSON é requisito da lib.

Contratos
  • IMovieRecommendationProvider com chatId. IChatHistoryRepository igual. TTL 1200s constante, não env.
