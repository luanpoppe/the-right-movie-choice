Migrar runtime de IA para @luanpoppe/ai

Atualizado em 2026-09-03

Contexto

O backend recomenda filmes e gera exemplos de query via wrapper local src/lib/langchain (Gemini + LangChain). Esta mudança troca esse runtime pela biblioteca pública @luanpoppe/ai, com OpenRouter como provedor primário, fallback nativo para Gemini quando a chave existir, e histórico de chat na memória da lib (checkpointer no Redis já usado), sem mudar HTTP, SPA nem cota/auth.

Decisões macro
  • Decisão: Adapters fazem new AI() no call site; lib/ai só constantes. Por quê: a lib já é facade. Alternativa descartada: singleton AiClient.
  • Decisão: IChatHistoryRepository adapta a memória da lib; chatId e TTL 20 min. Por quê: use case já orquestra load/save. Alternativa descartada: lib dona do thread; dual-write.
  • Decisão: OpenRouter primário, fallback nativo para Gemini. Só OPENROUTER_API_KEY obrigatória. Por quê: Gemini não é mandatório. Alternativa descartada: duas chaves sempre obrigatórias.
  • Decisão: Checkpointer no Redis existente; chaves antigas expiram; logs de provedor, latência e falha de schema. Por quê: chat efêmero. Alternativa descartada: Postgres/SQLite, migrar histórico, logar prompt.
  • Decisão: Unitário mocka AI no adapter; live opt-in local. Por quê: igual TMDB. Alternativa descartada: live na CI.

Features (executadas sequencialmente)
  1. ai-client — Pacote, env e AiModels; sem wrapper.
  2. recommendation-provider — Recommendation via new AI(), porta igual.
  3. query-examples-provider — GET /movie/queries via new AI().
  4. chat-memory — Adapter de IChatHistoryRepository na memória da lib (Redis + TTL 20 min + chatId).
  5. remove-langchain-wrapper — Remover src/lib/langchain e dependências LangChain diretas.

Escopo

Dentro: pacote; constantes; dois providers com new AI(); memória; env; logs nos adapters; limpeza LangChain.

Fora: SPA, cota/Bearer, Redis de refresh token, áudio/embeddings, agentes novos, contrato HTTP, live na CI.
